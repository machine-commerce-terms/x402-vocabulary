# Changes

## 1.0 (2026-11-16)

The first published version. It follows draft 0.1, written by nohumans.directory. The changes from that draft:

| Change | Why |
|---|---|
| Terms section added | The failure modes rest on these words. They are the definitions agreed by email on 13 and 15 November, with the two real differences shown side by side. |
| 1.1 No answer added | Draft 0.1 started at a reply. A call that gets no reply had no place. |
| 1.5 now covers the payment address | A quote that pays a different address from the listing is the same kind of difference as a different price. |
| 2.1 and 2.2 reworded | So the two cannot be read as one. |
| 2.3 says what a placeholder is | So everyone counts the same thing. |
| 3.2 Asked for more than quoted added | From nohumans.directory's note of 13 November. Draft 0.1 compared the quote with the listing; this compares the payment with the quote. |
| Buyer-side failure removed from stage 3 | It can happen at any stage. Principle 4 covers it. |
| Principle 5 added | Several failures happen both before and after payment. To a buyer those are different, so each failure records which. |
| Principle 6 added | An unreadable settlement is evidence of neither outcome. |
| 4.3 names an error under a success status | A 200 whose body is just an error message. |
| 4.4 and 4.5 defined against what the route publishes | This keeps them inside principle 3: usable, not correct. |
| 4.6 removed | A misjudged delivery is the instrument's mistake, not a failure of the call. Principles 4 and 7 cover it. |
| 5.1 reworded | To say what was observed: settled, failed, sent back. |
| 5.2 No settlement reference added | A buyer can be charged correctly and still be unable to reconcile the charge. |
| Late correction moved to principle 7 | It binds whoever publishes, not the seller. |
| Renumbered within each stage | Numbers are fixed from the first agreed version. |
| Usable answer defined by declared content type | With 4.6 removed, a fixed list of formats would count CSV and plain-text answers as unusable. |
